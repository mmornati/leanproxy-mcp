What the scanner looks for

Two kinds of cargo come through every MCP call: weight you pay for on every turn, and payloads that can hurt you. LeanProxy handles both in the same pass, before anything reaches your model provider.

Weight tokens you pay for

  • Router or passthrough Four router tools cost 318 tokens instead of every schema on every turn. Clients that already search their own tools get every tool listed as server__tool instead.
  • search_tools BM25 search across every server. A lookup costs 152 tokens on average, and it puts the right tool in the top 5 for 85.5% of 83 labeled intents.
  • Response governor Per-tool field projection, head/tail and structural truncation, dedup within a session, and paging back through read_result.
  • Response cache An opt-in, exact-match cache for read tools you allowlist, bounded by bytes.

Threats payloads that can hurt you

  • Secret redaction 29 built-in patterns, in both directions, on by default. Add your own, or switch on the high-entropy detector for keys no pattern knows.
  • Prompt injection guard Switch it on and a local classifier screens requests, tool results, resources and prompts. Each risk band can block, quarantine, redact or annotate.
  • Tool pinning Hashes every upstream tool definition and flags rug pulls, hidden instructions and invisible unicode until you approve them.
  • Per-tool policy Allow, deny or confirm by tool glob and by annotation. Calls to tools a server never advertised are refused.
  • Sandboxed servers Runs third-party stdio servers in a Docker or Podman container, with no network and no filesystem access by default.

Cleared what you can check afterwards

  • doctor security A read-only report mapped to the OWASP MCP Top 10, with --json for CI.
  • Savings report Built from real counters, broken down by server and by session.
  • OpenTelemetry Traces and metrics for every proxied call, exported over OTLP to the collector you already run.
  • tools pins and policy check See what changed upstream before you approve it, and test a rule before a call hits it.

Full methodology and raw numbers

Your client already searches its tools? Good.

Claude Code, Claude Desktop, Cursor and VS Code already defer and search large tool lists on their own. For them, LeanProxy stops hiding schemas behind a router. It lists every upstream tool as server__tool, with full metadata and tools/list_changed, and gets out of the way.

It still redacts, screens, pins and enforces policy on every listed tool and every call. And the response side doesn't depend on the mode: large tool results drop by 92.1% and repeated reads by 73.6% in the harness, whichever client you use.

Which mode each client gets, and why

Through the checkpoint in three steps

  1. Install the binary

    Homebrew or a release archive on macOS and Linux (amd64 and arm64), or go build from source.

    brew tap mmornati/leanproxy-mcp \
  https://github.com/mmornati/leanproxy-mcp
brew install leanproxy-mcp

  2. Put your servers behind it

    Add each server once to ~/.config/leanproxy_servers.yaml. Coming from Claude Code or OpenCode? leanproxy-mcp migrate imports what they already have.

    leanproxy-mcp server add filesystem -- \
  npx -y @modelcontextprotocol/server-filesystem ~/projects

  3. Point your client at LeanProxy

    Replace the servers in your client with one stdio server, or run a shared HTTP gateway with serve.

    # Claude Code; other clients: same command
claude mcp add leanproxy -- \
  leanproxy-mcp server run --stdio
